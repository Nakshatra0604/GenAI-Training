# Product Documentation Guidelines

Customer-facing documentation should be written for someone using the
product for the first time, avoiding internal terminology that customers
would not recognize. Each help article should focus on a single task, such
as "Export your data" rather than combining multiple unrelated tasks into
one long article.

Screenshots should be updated whenever the underlying interface changes
enough to make the screenshot misleading. Documentation is reviewed by
both a technical writer and the feature's product manager before
publishing, to check both clarity and accuracy.

Articles are tagged by product area so customers and support agents can
find related content easily. Outdated articles are archived rather than
deleted, so historical links do not break, but archived articles are
clearly marked as no longer current.
